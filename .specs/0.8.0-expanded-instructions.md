# Spec v0.8.0: Suporte a instruções Dockerfile adicionais

## Objetivo
Expandir docker-yaml para suportar 6 novas instruções Dockerfile: ADD, LABEL, VOLUME, HEALTHCHECK, SHELL, STOPSIGNAL.

## Instruções a suportar

### ADD
- Similar a COPY, mas com suporte a URLs e extração automática
- Schema: `{ src, dest, chown? }`
- Não suporta `afterRun` como COPY (ADD é mais para build-time)
- Ordenação: na seção `add`, após `copy`

### LABEL
- Metadados chave=valor
- Schema: objeto `{ key: "value", ... }`
- Exemplo: `label: { maintainer: "foo@bar", version: "1.0" }`
- Ordenação: após `expose` (metadados vêm depois de configuração)

### VOLUME
- Pontos de montagem
- Schema: array de strings ou objeto `{ paths: [...], ...? }`
- Exemplo: `volume: ["/data", "/logs"]`
- Ordenação: após `expose`, antes de `user`

### HEALTHCHECK
- Verificação de saúde do container
- Schema: objeto com `cmd`, `interval?`, `timeout?`, `retries?`, `startPeriod?`
- Exemplo: 
  ```yaml
  healthcheck:
    cmd: "curl http://localhost:3000 || exit 1"
    interval: 30s
    timeout: 10s
    retries: 3
  ```
- Ordenação: após `user` (configuração de runtime final)

### SHELL
- Altera shell padrão
- Schema: array de strings
- Exemplo: `shell: ["/bin/bash", "-c"]`
- Ordenação: logo após `from` (config base do ambiente)

### STOPSIGNAL
- Sinal para encerrar o container
- Schema: string (ex: "SIGTERM", "SIGKILL")
- Ordenação: após `entrypoint`/`cmd` (configuração de execução)

## Ordem padrão atualizada (v0.8.0)
FROM → SHELL → ARG → WORKDIR → COPY → ADD → RUN → ENV → EXPOSE → LABEL → VOLUME → USER → HEALTHCHECK → ENTRYPOINT → CMD → STOPSIGNAL

### validator.ts

- Regras semânticas (ex: HEALTHCHECK requer CMD ou ENTRYPOINT)
